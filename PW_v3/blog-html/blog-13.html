entry #13: glhf-chess

october-2026 [week 3]

Release week, or at least the week that found out what release week requires. The headline feature is a levelling system, which exists because Shards hit a daily cap and XP does not. The design detail I care about is the cap on it: captures and celebrated moments all happen on the player's own device, where the server has no way to check them, so the most a match can ever report is clamped — which makes cheating it worth about one extra game. The cap is the anti-cheat, and it is only acceptable because XP buys bragging rights and bonus Shards and never anything an opponent has to live with.

Then the bug of the month. The board had been rendering as a solid magenta block in every build since October 12. Removing an unused rendering package took one of its materials with it, and the tile and piece templates were both still pointing at that material. It survived because the things I looked at are drawn a different way — the frame around the board is built while the game runs, and the menu's army card is ordinary UI. The commit that removed the package checked the menu and the board preview, decided the board was fine, and never actually opened a match.

The economy also went live, and the very first call failed. The client was refusing the server's reply outright because it contained one field the client had never heard of — it was set to treat anything unfamiliar as an error. Adding the missing field would only have moved the problem to the next one, and a shipped game cannot work that way, since players on an old build have to keep playing when the server moves on. It now ignores what it does not recognise. Closed the week with a practice opponent, a match log that immediately caught a practice loss filing itself as a win, a daily challenge, and board hazards at roughly one match in fifty — rubble or mines, never both at once, because one kind is something you can take in on your first move and two is a puzzle nobody asked for.

Two smaller things closed the month out. The UI font had been Pixelify Sans, whose 5 is very nearly an S — which is a problem in a game whose screens are mostly numbers. 500 Shards read as SOO, 45:00 read as 4S:00. I put the candidates side by side with the actual strings the game shows and picked the one that could tell them apart.

And the Pawn got redrawn. The old one had feet and a flared base, and at board size the outline read as though it were growing little arms. The new shape is softer-shouldered and keeps the set's own eyes, which matters more than it sounds — it is the piece you see fourteen of.

october-2026 [week 2]

A polish pass that turned into two embarrassing discoveries, both the same shape: something installed, configured, and never actually run.

Ads had never been in a build. The code that talks to the ad service sits behind a compiler switch, and the switch had never been turned on — so that file had never been compiled by anything. The package was installed, the code was written, the account IDs were in place. Only the switch was missing, and nothing failed loudly enough to notice, because the fallback is a polite "ads are not set up in this build yet" rather than an error. I verified the fix by digging into the finished APK to confirm the code was really in there, rather than trusting a log line.

Then the reverse: a rendering package that was installed, configured and never used. The setting that would have switched it on had been empty the entire life of the project, so the game had always been drawing the ordinary way. Removing it took three more packages with it and the APK from 78MB to 72MB. I verified it the way a graphics change has to be verified, by building and looking, which is the part I only did half of — as the following week found out.

october-2026 [week 1]

October opened still on the roster push from the end of September, at a pace I would not recommend — twenty-odd units, same rule as before, each one claiming a verb nothing else does. The Twins are two pieces in one slot moving as one, the Courier announces its move two turns before making it, and the Bodyguard is a Queen, but only while your King is in danger.

Writing that many units that fast surfaced a problem with the board rather than with any one of them. Enough units now claim squares around themselves that a single highlight colour had stopped meaning anything, so those squares got their own colour and then split three ways by what they actually do to you. One of these commits also fixed a bug I had already patched five separate times in five separate units, by putting one guard in the shared path instead — which is the lesson I keep relearning every time I add content faster than I consolidate it.
